## 1. 文件

### 1.1 文件的数据结构

#### 1.1.1 文件控制块 FCB（File Control Block）

- **文件控制块**：用来存放控制文件需要的各种信息的数据结构，以实现**按名存取**
	- **基本信息**：文件名、文件的物理位置、文件的逻辑结构、文件的物理结构
	- **存取控制信息**：文件主的存取权限、核准用户的存取权限以及一般用户的存取权限
	- **使用信息**：文件的建立时间、上次修改时间等

### 1.2 文件的操作

#### 1.2.1 FAT32

##### **(1) 空闲簇查找**

1.   FAT表中，从第二个簇开始强行暴力每一个位置

```c
// 截断高 4 位保留位（FAT32 实际只使用低 28 位）
uint32_t entry_value = fat_table[N] & 0x0FFFFFFF;

if (entry_value == 0x00000000) {
    // 整个 32 bit 全部为 0，说明第 N 号簇是【空闲簇】
}
```

2.   FAT32 引入了一个特殊的扇区，叫做 **FSInfo（File System Information Sector）**（通常在第 1 扇区）。FSInfo 结构体中记录了两个极其重要的字段：

     `FSI_Free_Count`：当前文件系统中**剩余空闲簇的总数**（如果为 `0xFFFFFFFF` 则代表未知，需要扫描）

     `FSI_Nxt_Free`：**上一次分配的空闲簇号（或查找起点）**。

空闲簇查找可以用于文件增删以及创建新文件

##### **(2) 文件数据读取**

1.  通过目录项，找需要读取文件所在的开始簇位置
2.  如果文件大于一个簇，开始簇位置的值为下一个簇的位置，可以顺着这个簇链一直查找，直到结束簇出现。

##### **(3) 文件删除**

1.  文件删除的时候，根目录中该目录项的信息并不会被删除，而是将该目录项标记为删除状态
2.  FAT表中该文件所占用的簇号，会被标记为0，表示该簇为未使用的簇。
3.  该文件所在簇号所对应扇区的实际文件数据不会被擦除，文件里面的数据还是存储在删除上。

#### 1.2.2 ext2文件系统

##### **(1) 空闲块查找**

有`inode bitmap`和`block bitmap`来管理空闲分区

##### **(2) 文件数据读取**

1.   通过目录文件的data block中提取目录项，可以得到inode，见 [Inode 的目录项](#inode-的目录项)
1.   inode再去inode table里面找到对应项目
1.   再去data block中提取对应的数据

##### **(3) 文件删除**

1.   从父目录的目录项（Directory Entry）中解除映射，见ext2目录项。通过调整目录项的长度（`rec_len`）来跳过它，假装删除了这个目录项
2.   递减 Inode 的硬链接计数，如果为0则真的要删除了 
3.   释放数据块（Data Blocks）与 Block Bitmap
4.   再释放 Inode 节点与 Inode Bitmap

### 1.3. 文件的物理结构

#### 1.3.1 连续分配

- 文件的目录项记录**起始块号**和**所占用的块数**
- 要求**每个文件在磁盘上占有一组连续的块**

#### 1.3.2 文件链接分配

##### 1. 隐式链接

目录项中记录了文件存放的**起始块号**和**结束块号**

每个文件对应一个磁盘块的链表，磁盘块分布在磁盘的任何地方

除最后一个盘块外，每个盘块都含有指向文件下一个盘块的指针，这些**指针对用户是透明的**

**缺点**：

- 查找效率低，磁盘IO次数多
- 稳定性低，文件盘块中的任何一个指针出问题，都会导致文件数据的丢失

##### 2. 显式链接

典型代表为**FAT32系统**

FAT32系统中的FAT表，称为**文件分配表 FAT（ File Allocation Table）**。文件目录中只需记录**文件的起始块号**，后续块号可通过查 FAT，类似链表一样的数据结构。

文件分配表一般**常驻内存**

- **优点**：
  - 地址转换时不需要访问磁盘，直接访问**内存中的FAT**，因此文件的访问效率更高
- **缺点**：
  - 文件分配表的需要占用一定的存储空间

#### 1.3.3 索引分配

-   间接索引块（Indirect Block）本质上是一个**普通的数据块**，里面存的内容是一个**整数数组**，每个整数对应一个**数据块的编号**

>   注意不是目录项，也不是inode，也不是Block
>
>   而是**block**在**block_table**中的地址，也就是**数据编号**（数组下标）一般是uint32_t

```c
typedef struct ext2_inode{
	...
    uint32_t  i_block[15]; // 数据块指针（直接+间接，共15个）
    // 文件数据块的指针数组（共 15 个指针，分为 3 类：
    // 0-11：直接指针，直接指向存储文件内容的数据块
    // 12：一级间接指针，指向一个存储数据块编号的间接块
    // 13：二级间接指针，指向一个存储一级间接块编号的块
    // 14：三级间接指针，指向一个存储二级间接块编号的块）
	...
}__attribute__ ((packed)) ext2_inode_t;
```

#### 2.2.3 树形目录结构

- **定义**：
	- 当用户要访问某个文件时，用文件的路径名标识文件，**文件路径名是个字符串**，由从根目录出发到所找文件通路上所有目录名与数据文件名用分隔符“/”链接而成
	- 从根目录出发的路径称为**绝对路径**
	- 当层次较多时，每次从根目录查询会浪费时间，于是加入了**当前目录**（又称**工作目录**），进程对各文件的访问都是相对于当前目录进行的
	- 当用户要访问某个文件时，使用**相对路径**标识文件
	- 不同的用户的文件，文件名可相同可不同
	- 大多 OS 采用这种目录结构
- **优点**：
	- 可以很方便的对文件进行分类
	- 能够有效地进行文件的管理和保护
- **缺点**：
	- 不便于实现文件共享
	- 查找文件增加了磁盘访问次数，会影响查询速度

#### 2.2.4 无环图目录结构

**定义**：

在树形目录结构上，增加一些指向同一节点的有向边，使整个目录成为一个**有向无环图**
- 可以**用不同的文件名指向同一个文件**，甚至可以指向**同一个目录**【共享同一目录下的所有内容】
- 需要为**每个共享结点设置一个共享计数器**，用于记录此时有多少个地方在共享该结点
- 用户提出删除结点的请求时，只是删除该用户的 FCB、并使**共享计数器减 1**，并不会直接删除共享结点
- 只有共享计数器减为 0 时，才删除结点

### 2.2 文件共享

- 文件共享使多个用户共享同一个文件，**系统只需保留该文件的一个副本**

#### 2.3.1 基于索引节点的共享方式（硬链接）

硬链接就是多个 目录项 指向一个inode
- 文件的物理地址和其他文件属性信息放在索引节点中
- 索引节点中需要有链接计数 count
- 某用户想删除文件时，只是删除该用户的目录项，count--
- 只有 count == 0 时才能真正删除文件数据和索引节点，否则会导致指针悬空

- **特点**：查找速度比软链接快

#### 2.3.2 基于符号链的共享方式（软链接）

在一个 Link 型的文件中记录共享文件的存放路径
- OS 根据路径一层层查找目录，最终找到共享文件
- 只有文件主才拥有指向索引节点的指针
- 共享文件的其他用户只有该文件的路径名，并不拥有指向其索引节点的指针

**特点**：

- 访问共享文件时可能多次地读磁盘，增加了访问文件的开销
- 实现网络文件共享时，只需提供该文件所在机器的网络地址及文件路径名

| **共享类型**                               | **实现机制**                                                 | **能否为目录创建？**                                         | **是否会产生环？**                                           |
| ------------------------------------------ | ------------------------------------------------------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **硬链接** (Hard Link)                     | **基于索引节点的共享**。多个目录项指向同一个物理 Inode 号。  | **不能**（Linux 严禁用户为目录创建硬链接，就是为了防止目录结构出现环，导致死循环遍历）。 | **不能**。完全符合无环图定义。                               |
| **软链接 / 符号链接** (Soft/Symbolic Link) | **基于路径名的共享**。快捷方式本身是一个独立的新文件，其数据块里存放的是目标文件的**路径字符串**。 | **可以**。用户可以自由地为目录创建软链接。                   | **可以**。因为可以指向目录，如果 A 的软链接指向 B，B 的软链接指向 A，目录检索时就会形成**环**。 |

### 3.1 文件系统的基本概念

- **分类**：
  - **磁盘的文件系统**：
  	- 它是直接把数据存储在磁盘中，比如 Ext 2/3/4、XFS 等都是这类文件系统

#### 3.2.2 Linux VFS 在内存中的结构

- 内存中的信息用于管理文件系统并通过缓存来提高信息，磁盘读写还是太慢了

##### 1. 系统挂载时（Mount）加载至内存的数据

-   **VFS 超级块对象 (`struct super_block`)**

    Linux 读入磁盘 Ext2 的超级块（Super Block），并在内存中构建这个 VFS 超级块对象。

-   **Ext2 专属超级块信息 (`struct ext2_sb_info`)**

-   **块组描述符表缓存 (`struct ext2_group_desc`)**

##### 2. 文件访问与打开时（Open/Read/Write）建立在内存的数据

-   **VFS 索引节点 (`struct inode`) 与 Ext2 节点信息 (`struct ext2_inode_info`)**

    当访问某个文件或目录时，操作系统将磁盘 Inode Table 中的 `ext2_inode` 结构读入内存，并填充为一个标准的内存 `struct inode`（包含文件大小、权限、`i_block[15]` 指针表等）。

    *特点：* 内存中的 `struct inode` 还会包含脏页标记、信号量、引用计数等磁盘上没有的运行时信息。

-   **目录项缓存 (`struct dentry`)**

    建立路径名（如 `/usr/bin/gcc`）与内存 `struct inode` 之间的映射关系。

    特点：* VFS 将解析过的路径解析结果保存在 `dentry` 结构体组成的树状缓存（dcache）中，以避免每次查找文件都要去盘上解析目录项。

-   **页缓存 (`struct address_space` / Page Cache)**

    文件内容的内存缓存。当从磁盘读取数据块（包括真正的文件内容、间接索引块）时，内核会将其按 4KB 页为单位装载到内存 Page Cache 中。

##### 3. 进程管理文件状态时（Process Dynamic Structure）建立在内存的数据

-   **系统级打开文件表 (`struct file`)**

    代表一个已被打开的文件会话。记录当前文件的读写偏移量（`f_pos`）、打开模式（只读/只写）、文件的引用计数，并指向对应的内存 `dentry` 和 `inode`。

-   **进程级打开文件表 (`struct files_struct`)**

    存在于进程的 `task_struct` (PCB) 中，内部包含一个文件描述符数组（`fd_array`）。`fd_array[fd]` 的每一个元素指针都指向系统级打开文件表中的某一个 `struct file`。

### 3.3 外存空闲空间管理

#### 3.3.1 空闲表法

- 属于**连续分配方式**，为每个分区文件分配一块连续的存储空间
- 每个空闲区对应一个**空闲表项**，包括：该空闲区的第一个空闲盘块号 和 该空闲区的空闲盘块数
- 回收磁盘空闲区域类似`并查集算法`，可以合并相邻的左右空间

#### 3.3.2 空闲链表法

##### 1. 空闲盘块链

-   将tsoding的arena.h抽象出来为磁盘模式

##### 2. 空闲盘区链

每个空闲盘区的**首个磁盘块**中，会记录两个核心元数据：

1.  **本盘区的大小**：包含多少个连续的盘块（Block 数量）。
2.  **指针**：指向下一个空闲盘区首块的磁盘物理地址。

-   分配盘区的方法与内存的动态分区分配类似，通常采用首次适应算法

-   回收盘区时，同样也要将回收区与相邻接的空闲盘区合并

#### 3.3.3 位示图法

-   ext2系统使用的就是位示图法

-   利用二进制的一位来表示磁盘中一个盘块的使用情况，磁盘上所有的盘块都有一个二进制位与之对应【0 代表盘块空闲，1 代表盘块已分配】

#### 3.3.4 成组链接法

![image-20260830204409965](/home/ping/Second_Attempt/408/OS/assets/image-20260830204409965.png)

成组链接法本质上是一个**基于 Block 的嵌套栈结构**：

##### 1. 定义

-   Free Blocks Grouping（空闲块分组）：把磁盘上所有的 Free Blocks 每 100 个分为一组（Group）。
-   每组的第一个 Block 不存普通数据，而是充当 **Metadata Block**，记录：
    1.  `next_group_count`：下一个 Group 的 Free Block 总数。
    2.  `free_blocks_array[]`：下一组中所有 Free Block 的 Block Number 列表。
-   内存空闲块号栈：操作系统在 Memory（超级块 SuperBlock）中维护一个专用 Stack，内存中永远只保存当前最新这一组的 Block Numbers

##### 2. 盘块分配

Stack 的 Top 指针一开始指向空闲块分组的最后一个

当进程申请分配一个 Block 时，操作系统执行 **POP** 操作：

1.  检查栈顶指针

    读取内存 Stack 的 Top 指针，找到对应位置的 Block Number

2.  普通分配

    如果指向的**不是 Stack Bottom（栈底）**：直接把该 Block Number 分配给用户，Stack Pointer 上移（对应图片），`stack_count --`。

3.  栈底分配与连锁读取

    如果指针恰好指向 **Stack Bottom**（说明这是当前 Group 里的最后一个可用块，且它本身就是下一组的 Leader Block）：

    -   **Step 1:** 先发起 Disk I/O，将该 Leader Block 中的内容（即 Next Group 的 100 个 Block Numbers）**Read 入内存 Stack 中**，覆盖旧 Stack。
    -   **Step 2:** 内存 Stack 被更新为全新的 Group 数据。
    -   **Step 3:** 将原栈底的这个 Leader Block 作为普通 Block **Allocate 给用户**。
    -   **Step 4:** `stack_count--`。

##### 3. 盘块回收

当文件被 Delete，用户归还一个 Block 时，OS 执行 **PUSH** 操作：

1.  **Normal Recovery（栈未满 / 普通压栈）**：

    如果当前内存 Stack 的 `stack_count < 100`：

    直接将回收的 Block Number 压入 Stack 顶部，Stack Pointer 下移，`stack_count++`。

2.  **Stack Overflow & Push to Disk（栈满溢出 / 刷盘建新组）**：

    如果当前内存 Stack 已经达到 `stack_count == 100`（栈满）：

    -   **Step 1:** 将刚刚回收的这个 Block 作为**新的 Leader Block**。发起 Disk I/O，把当前内存 Stack 中的全部 100 个 Block Numbers **写到这个新回收的 Leader Block 中**。
    -   **Step 2:** 清空内存 Stack，将这个新 Leader Block 的 Block Number 设为内存 Stack 的**新栈底（Stack Bottom）**。
    -   **Step 3:** 重置内存 Stack 的计数器 `stack_count = 1`。

### 3.4 虚拟文件系统 VFS

- **虚拟文件系统（VFS）**：屏蔽了不同文件系统的差异和操作细节，向上为用户提供了文件操作的同一调用接口
- **特点**：
	- 向上层用户进程提供统一标准的系统调用接口，屏蔽底层具体文件系统的实现差异
	- VFS 要求下层的文件系统必须实现某些规定的函数功能（open/read/write）
	- 一个新的文件系统想要在某 OS 上被使用，则必须满足 VFS 的要求

#### 3.4.1 加入新文件系统过程

1.   读取磁盘超级块：内核开机或执行 mount。

     操作系统读取目标分区的磁盘超级块，获取该文件系统的所有底层参数。

2.   实例化 VFS 超级块：内存分配。VFS 在内核内存中新建一个通用的 `struct super_block` 对象，把刚才读到的磁盘参数填进去。

3.   绑定操作函数指针：泛型化设计。VFS 会把底层的函数指针赋值给通用超级块

4.   加入 VFS 全局链表：统一纳管。这个内存超级块会被挂载到 VFS 全局的超级块链表（`super_blocks`）中。

### 3.5 文件系统挂载

**文件系统挂载（mounting）**：文件系统在进程使用之前必须先挂载到某个目录，此后便可通过这个目录来访问设备上的文件

**挂载过程**：

1. 新挂载的文件系统，要向VFS注册**操作接口**，也就是[3.4.1 加入新文件系统过程]()
3. 将新文件系统加到**挂载点**，也就是将新文件系统挂载到某个父目录下
